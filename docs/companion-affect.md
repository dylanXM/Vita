# 伴侣情绪与主动行为

## 状态与事实

- 普通聊天、约会聊天、自发联系复用原有生成请求，附带可选 `affect` JSON 字段；不单独调用模型判断情绪。
- 后端校验情绪枚举、行动枚举、原因长度和数值范围。无效的可选字段丢弃，正常回复仍可保存；结构化结果不直接作为消息发送。
- `companion_affect` 保存情绪原因、主动行为及版本；`companion_affect_events` 按原因去重。心情、压力、精力和社交精力仍存于 `companion_states`，限制在 0–100。
- 模型返回的版本必须与当前状态相同；过期的状态变化不覆盖新经历。回复及情绪在同一事务保存，失败一起回滚。
- 生活事件改变总体心情；最近一次人际情绪单独保留在模型上下文中。开心的生活事件不直接清除暂停联系状态。

## 行为

- 自发联系、生活分享、记忆跟进和对话跟进共用主动联系条件：暂停期、精力、当前活动、连续未回应次数及已有账号频率/安静时段限制。
- 连续未回应达到两条后不再不断开启话题；直接回复、约会履约不受这条限制。
- 等待累计六个非安静时段小时后减少主动；两条主动联系等待超过二十四个非安静时段小时后暂停主动。每个阶段仅应用一次；不认定用户故意拒绝，不扣关系分。
- `slow` 暂停主动六小时，`space` 暂停二十四小时。没有新事实不会在每轮调度重复扣分。
- 用户回来、道歉、送礼或拜访不自动恢复情绪。拜访仍记录互动和现有关系进度，不再固定增加心情。
- 已支付约会正常履约，态度和场景内反应可延续情绪，不增加收费或退款分支。

## 模型开销与失败

- 定时情绪演进不调用模型。短情绪字段与回复共用原请求；只向模型补充当前状态和最近一条人际情绪，不发送整本状态历史。
- 生活分享在调用前检查资格，并读取最近六条普通聊天。原有分享请求可以决定不发送；不再强制另起话题。
- 每个生活事件原子认领发送决策，最多三轮，间隔至少三十分钟，避免异常结果或多 worker 导致每轮重复调用。每轮内部保留原有模型路由及供应商 fallback。
- 无效 JSON 不发送；无效情绪字段不触发修复模型调用。约会反应调用失败时复用本地化文案，并以关系阶段/现有压力计算有限的后备影响。
