# 自然分条回复与主动追问

## 不依赖生活事件的主动聊天

主动触达现在有两条路径：原有生活事件分享，以及独立的人物主动聊天。独立路径不查询可分享事件作为发送前提，不创建虚构事件、不附事件引用卡，以普通文字消息和现有推送方式交付。

模型读取人物性格、说话方式、关系、当下心情／精力／压力／社交精力、近期普通聊天和记忆，再自行决定是否发送。动机可以是分享一个完整笑话、短暂的情绪或小牢骚、想念、具体关心、好奇或接续旧话题；可以选择安静，不强制轮换类型，也不把每条消息写成活动日报。情绪可以是情绪本身，不为解释心情编造事件；不能编造用户状态、现实新闻、他人行为或事情结果。浪漫程度服从当前关系与用户边界，不催回复、不因沉默施压。

沿用主动联系开关、访问权限、每日统一额度、最小发送间隔和免打扰。睡眠、工作、学习、通勤、进行中的共同活动、待发回复／追问以及过低精力或社交精力期间不发送。连续两次主动联系未得到用户回复时，独立路径暂停。后台按用户最多每九十分钟评估一次，评估记录持久化到已有 agent_runs，模型选择不发也不会下一轮立即重新请求。九十分钟是模型评估间隔，不是发送承诺；原有用户发送间隔仍然优先。

多人／多 worker 共用用户行锁抢占评估和最终发送额度；生成期间聊天记录改变，或权限／免打扰／人物状态不再满足发送条件时，会在提交前取消。文字消息和 notification_outbox 在同一事务中写入。生活分享仍保留，独立主动聊天优先获得一次决策机会，避免事件永远占满每日预算。

新增 Backend internal/agent/spontaneous_contact.go，接入现有 DispatchDueProactive；Admin 的既有“触发主动联系”入口也会走该决策。没有新 API、客户端字段要求或数据库迁移。仅需先上线 Backend；Admin、Webapp 与旧 App 可直接接收普通文字消息，符合原部署顺序。

本次仅进行人工源码与字段／消息合同检查，未执行 test、check、build、gofmt 或供应商调用，未验证真实模型输出与设备推送。快速验证：在非免打扰时间，为已聊天、可访问、开启主动联系的普通人物保留发送额度，在 Admin 触发主动联系；查看 spontaneous_contact_decision 调用和 spontaneous_contact 评估记录。send=false 是正常安静决策；send=true 时应出现不带事件卡的普通文字消息。再次触发不应重复调用模型；生成期间发送新消息应取消旧决策发送。

普通伴侣聊天使用结构化生成：`messages` 包含 1～3 条自然短消息；`follow_up` 可为空，或描述未完成的话题、伴侣自己的动机及延迟时间。生成决策读取伴侣性格、说话方式、关系和当前 mood / energy / stress / social_energy，以及生活状态和用户边界。按交流意图分条，不按标点机械截断。可选追问参数无效时丢弃该计划，正常回复仍交付。

第一条即时返回；后续消息持久化到 `companion_conversation_queue`，间隔 6～8 秒发送。后台恢复时也保持至少 6 秒间隔，不一次补发整个列表。App 现有轮询显示消息，在后续消息发送完成之前保持回复中状态。普通聊天的生活事件关联保留，沉浸式约会的场景 JSON 合同不变。

追问由模型结合人物状态决定是否安排，1 分钟到 2 小时只是允许的调度范围，不是到点必发。到期使用 `text_proactive` 模型重新读取当前性格、心情、精力与对话，返回 `send=false` 时取消。不同人物可主动继续话题，也可选择保持安静。不开启新的媒体生成或消费。

发送条件：
- 用户尚未发送新消息，前一轮拆分消息已经交付；新用户消息会取消旧轮次未发内容，生成期间收到回复也会在提交前拦截。
- 伴侣仍可访问，主动联系和友情已开启，未进入管理员接管。
- 睡眠、工作、学习、通勤中暂不追问，稍后重新判断；过期计划取消。
- 遵守每个用户的主动联系开关、每日限额、最小间隔和免打扰。聊天正在前台轮询时允许跟进当前对话，但每日限额和免打扰仍有效。用户已在其他场景活跃时沿用现有后台联系限制。
- 追问计入主动联系的统一预算；不会在无人回复时连续创建新的追问链。
- 服务重启可恢复队列，发送事务和状态更新保证不重复交付。临时失败最多三次；被用户取消的内容不会再发出。

## 上线

先执行 `backend/migrations/20261013_conversation_turns.sql`，再上线 Backend + Admin（Admin 无代码改动），App 后上线。原购买、媒体和聊天消息合同保留；旧 App 仍能通过消息轮询显示分条回复，新 App 补齐连续回复中的状态。需启用 Agent worker、配置 `text_chat` 与 `text_proactive` 路由。

## 快速验证

1. 与一个精力充足、好奇或体贴的伴侣聊一个未完成的话题，观察 1～3 个独立气泡按几秒间隔出现。
2. Admin 模型调用入参、回复中可查看结构化 `messages` 与可选 `follow_up`，追问到期会出现独立的 `conversation_followup_decision` 调用；是否发送由当时的人物状态决定，不能要求每次必发。
3. 第一条出现后立即补充消息，确认旧轮次尚未发出的气泡和追问取消。
4. 将主动联系每日限额设为零或处于免打扰时间，确认不发送追问。

真实供应商和设备尚未实测。自动化覆盖 PostgreSQL 全回复流程、分条间隔、幂等重试、并发 worker、生成期间用户回答、send=false、免打扰、睡眠、频率和崩溃恢复；App 覆盖首条后保留待续状态及并发发送。
